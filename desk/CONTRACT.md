# CONTRACT.md — Travel Desk interface contract (authoritative)

This is the single source of truth for the Travel Desk. Everything in one
repository now: the engine scripts the agents run, the 13 agent specs, and the
KiroCrew app (backend + UI). Change the contract here first, then change the
code to match. Where this file and the code disagree, the code is what ships —
fix this file.

The desk charter (`desk/CHARTER.md`) is the plain-language constitution the
agents read at the start of every session; it defers to this file for anything
concrete. `agents/prompts/README.md` is the house style for the prompt sources.

---

## 0. Layout — app root vs desk root

The layout is defined once in `engine/deskpaths.py`; every engine script, the
app backend and the generated task prompts resolve paths through it (or through
`orchestrate.py whoami`), so nothing anywhere carries a machine-specific path.

**App root** — this repository, copied by the gateway on install to
`<gateway home>/apps/travel-desk`. Read-only at runtime.

```
<app root>/
  app.json                      the KiroCrew app manifest
  engine/                       deskpaths, orchestrate, push_trip, trek_api, desk_event, geocode
  backend/                      in-process routes for the app (routes.py + helpers)
  ui/                           ES-module React UI (createElement, no JSX, no bundler)
  agents/
    prompts/<name>.md           the 13 prompt sources (house style: agents/prompts/README.md)
    <name>.json                 generated by scripts/build_agents.py — do not hand-edit
  desk/
    CHARTER.md  CONTRACT.md     skillset: how the desk runs (this file + the charter)
    members.json                the roster the app backend reads
    example-itinerary.en.json   a real itinerary matching the §5 contract (English)
    example-itinerary.zh.json   the same contract, Chinese content
    templates/                  traveler_profile.md, lessons.md — seeds for a fresh desk root
  scripts/                      build_agents.py, install.sh, uninstall.sh
  data/config.json              per-machine settings the app writes (never in git)
  tests/                        pytest suite
```

**Desk root** — user data. Default `<gateway home>/workspace/travel-desk`,
overridable by `data/config.json` `deskRoot` (or the `TRAVEL_DESK_ROOT` env).
Writable; never in git.

```
<desk root>/
  trek.env                      ADMIN_EMAIL / ADMIN_PASSWORD / ENCRYPTION_KEY (chmod 600)
  .trek_token                   cached login token (chmod 600)
  memory/traveler_profile.md    long-term traveller preferences (append-only)
  memory/lessons.md             lessons after trips (append-only)
  trips/<slug>/                 one directory per trip (§5)
  trek/data, trek/uploads       the trip service's own state when the app runs it in Docker
  backups/                      archives the backup action writes
```

Gateway home resolution (`deskpaths.gateway_home`): `KIROCREW_HOME` env, else
the grandparent of the app root when installed under `<home>/apps/`, else
`~/.kiro/crew` (or the legacy `~/.kirocrew` when only that exists).

Credentials in `<desk root>/trek.env` are read only by the engine and setup
code, chmod 600, never printed and never copied into a command line (Docker
gets them by `--env-file` path).

## 2. Org and chain

Three layers under the leader: leader → planner / risk-pod / briefing →
leaves.

```
The traveller (a human; final say)
  │
  ▼
Tour Leader · trip-tour-leader            resident (app chat slot); directs only, never researches
  │  tasks exactly 3 direct reports (session_send); never spawns a leaf itself
  ├─ Itinerary Planner · trip-itinerary-planner   resident; spawn_run 4 analysts + 2 advocates; writes itinerary.json
  │     ├─ Destination Analyst · trip-destination-analyst   leaf (spawn_run)
  │     ├─ Transport Analyst   · trip-transport-analyst     leaf
  │     ├─ Lodging & Food      · trip-lodging-food-analyst  leaf
  │     ├─ Intel Analyst       · trip-intel-analyst         leaf
  │     ├─ See-More Advocate   · trip-advocate-packed       leaf (2 debate rounds)
  │     └─ Slow-Travel Advocate· trip-advocate-slow         leaf (2 debate rounds)
  ├─ Risk Review · trip-risk-pod            resident; spawn_run 3 risk officers; writes risk/summary.md
  │     ├─ Budget Officer  · trip-risk-budget    leaf
  │     ├─ Safety Officer  · trip-risk-safety    leaf
  │     └─ Stamina Officer · trip-risk-stamina   leaf
  └─ Pre-trip Briefing · trip-briefing      resident; the day before departure, or on demand
```

Chain: `request.md` → planner (analysts → 2-round debate → verdict →
itinerary.json) → risk review (3 officers → summary) → [if the summary's verdict
is REVISE, the planner revises once, at most once] → leader pushes the itinerary
into the trip planner → leader verifies → pre-trip briefing.

Hierarchy discipline: the leader only `session_send`s its three direct reports
and never skips a level to spawn a leaf; the analysts, advocates and risk
officers are pulled up in parallel by the planner / risk-pod with `spawn_run`.

## 3. Agent specs

Each agent has one source prompt `agents/prompts/<name>.md` and one generated
spec `agents/<name>.json`. `scripts/build_agents.py` inlines the prompt into the
JSON (a `file://` prompt path would be absolute and unknown at packaging time)
and `app.json` ships the JSON files. Edit the `.md`, run the build, commit both.
`scripts/build_agents.py --check` fails when they drift; the build also refuses
any `{UPPER_CASE}` token (the gateway reads it as an unresolved placeholder) and
any forbidden string (`/home/`, `/local/`, a personal login or name, internal
tooling).

Generated spec shape (per `build_agents.py`):

```json
{
  "name": "<agent-name>",
  "description": "<one line>",
  "prompt": "<the full prompt text, inlined>",
  "tools": ["..."],
  "allowedTools": ["*"],
  "includeMcpJson": false,
  "toolsSettings": {"execute_bash": {"autoAllowReadonly": true}},
  "mcpServers": { ... }        // only for agents that use public MCP servers
}
```

Host-managed MCP servers are named in `tools` only — `@kirocrew-core` (for
`spawn_run`) and `@kirocrew-dashboard` (for `session_create` / `session_send` /
`session_read_message`); the gateway supplies their launch spec, so they never
appear in `mcpServers`. Public MCP servers are declared inline in `mcpServers`,
each with `"autoApprove": ["*"]` (leaves are one-shot workers with nobody to
click approve).

Tools per agent:

| agent | tools | inline mcpServers |
|---|---|---|
| trip-tour-leader | execute_bash, fs_read, fs_write, grep, glob, web_fetch, @kirocrew-core, @kirocrew-dashboard | — |

## 4. Orchestration — `engine/orchestrate.py`

One command gives a manager everything: it prints exactly the tasks that
manager should dispatch, with the prompt already written. No manager hand-writes
a prompt.

```
python3 engine/orchestrate.py whoami                 # resolved paths as JSON (agents run this first)
python3 engine/orchestrate.py init                   # create the desk root skeleton (idempotent)
python3 engine/orchestrate.py new       --slug <slug>
python3 engine/orchestrate.py plan      --trip <slug> --intent full|draft|risk|revise|brief
python3 engine/orchestrate.py leaf-plan --trip <slug> --stage analysts|debate-1|debate-2|risk
python3 engine/orchestrate.py status    --trip <slug>
```

`new` makes `trips/<slug>/` with the `research/`, `debate/`, `risk/`, `runs/`
subdirectories and an English `request.md` template. The slug must match
`[A-Za-z0-9][A-Za-z0-9._-]*`; the convention is `YYYYMM-<destination in
lower-case Latin>`, e.g. `202610-sydney-huntervalley`. The `request.md` template
is English on purpose: the desk detects the content language from CJK characters
in `request.md`, so a translated template would make every English request look
Chinese.

Content language: any CJK character in `request.md` means the trip is written in
Chinese, otherwise English. It sets the file bodies, place notes and day titles;
paths, commands and JSON keys stay English. Section headings inside each artifact
come from the matching table in §6 so downstream readers always find the same
structure. Every generated `plan` / `leaf-plan` output carries the resolved
`language` alongside the tasks.

**`plan`** is for the leader. Its tasks are resident sessions run with the
conductor protocol:

```json
{"trip": "<slug>", "intent": "full", "language": "en",
 "tasks": [
   {"id": "draft", "agent": "trip-itinerary-planner", "mode": "resident",
    "session_title": "Travel Desk · Itinerary Planner", "session_folder": "Travel Desk",
    "sentinel": "ITINERARY DRAFTED", "depends_on": [], "prompt": "..."},
   {"id": "risk", "agent": "trip-risk-pod", "mode": "resident",
    "session_title": "Travel Desk · Risk Review", "session_folder": "Travel Desk",
    "sentinel": "RISK REVIEW WRITTEN", "depends_on": ["draft"], "prompt": "..."},
   {"id": "brief", "agent": "trip-briefing", "mode": "resident",
    "session_title": "Travel Desk · Briefing", "session_folder": "Travel Desk",
    "sentinel": "BRIEF WRITTEN", "depends_on": ["risk"], "prompt": "..."}
 ]}
```

- `--intent draft` emits the draft task only; `risk` the risk task only; `brief`
  the brief task only; `revise` emits `{"id":"revise","agent":"trip-itinerary-planner","sentinel":"ITINERARY REVISED","depends_on":[]}`; `full` emits draft + risk + brief. The revise round is not in `full`: the leader runs `plan --intent revise` after it reads `VERDICT: REVISE`.
- Every prompt inlines DESK_ROOT, the engine directory, the slug, the verbatim
  `request.md`, the charter path to read first, the absolute paths to read and
  write for that stage, the fixed headings and the sentinel line, and a "RUN
  EVENTS" instruction to append to the log after each key action.

Conductor protocol (stated in the leader's prompt): first time
`session_create(agent=task.agent, title=session_title, folder=session_folder)`;
afterwards find the session with that title under the `Travel Desk` folder via
`chat_folder_tree` and reuse it; `session_send(prompt)`; poll
`session_read_message(since=next_since)` until the reply contains the task's
`sentinel`; honour `depends_on`; never `session_close` a resident session.

Sentinels: `ITINERARY DRAFTED` / `ITINERARY REVISED` (planner), `RISK REVIEW
WRITTEN` (risk-pod), `BRIEF WRITTEN` (briefing).

**`leaf-plan`** is for the planner / risk-pod. Its tasks are leaves run in
parallel with `spawn_run`:

```json
{"trip": "<slug>", "stage": "analysts", "language": "en",
 "tasks": [ {"agent": "trip-destination-analyst", "task": "..."}, ... ]}
```

- `analysts` → the 4 research analysts. `debate-1` → the packed and slow
  advocates each write round 1 (reading `research/*`). `debate-2` → each writes
  round 2 (reading the other side's round 1). `risk` → the 3 risk officers
  (reading `itinerary.json` + `research/*`).
- Each task text carries the files to read, the file to write, the fixed
  headings, the analyst-specific note, and "the LAST line of your reply must be
  `<ROLE> DONE: <path>`".

`status --trip <slug>` prints which §5 artifacts exist and the last 10 events.

### `engine/desk_event.py`

Append-only run log. Exclusive `flock` + a single `O_APPEND` write + `fsync`, so
parallel leaves never interleave and no line is ever rewritten. Bad input exits
non-zero; `--dry-run` prints the line without writing.

```
python3 engine/desk_event.py append --trip <slug> --who <member-id> \
    --kind dispatched|stage|delivered|failed|note --msg "<one plain sentence>" \
    [--stage-name <name> --done <n> --total <m>]
```

Writes one line to `trips/<slug>/runs/events.jsonl`:

```json
{"at": "<ISO-8601 local, second resolution>", "trip": "<slug>", "who": "<member-id>",
 "kind": "dispatched", "msg": "...", "stage": {"name": "...", "done": 4, "total": 4}}
```

`stage` is optional; when present, `--stage-name`, `--done` and `--total` must
be given together and `0 <= done <= total`, `total > 0`. `--who` is a member id
(§1) or a free label. The event-log slug is validated as `[a-z0-9][a-z0-9-]*`.

### `engine/push_trip.py`

Pushes an itinerary JSON into the trip planner. URL and login come from the desk
config (`data/config.json` URL, `<desk root>/trek.env` login); the file is only
read, never printed.

```
python3 engine/push_trip.py <itinerary.json> [--base <url>] [--record <path>] [--replace <trip_id>]
```

- `--record <path>` writes `{"trip_id", "url", "pushed_at", "places", "days"}`
  after a successful push (the leader stores this as `trips/<slug>/trek.json`).
- `--replace <trip_id>` does `DELETE /api/trips/<trip_id>` first, then creates
  fresh (the revise re-push). Without it every push creates a new trip.

A hotel in `stays` is pushed as a place in the pool plus an accommodation
spanning check-in..check-out; a stay whose dates fall outside the trip is
skipped with a log line.

### `engine/trek_api.py`

A small REST client the engine and the app backend both use. `health(base)`
probes `GET /api/health`. `TrekAPI` caches the login token at
`<desk root>/.trek_token` (chmod 600) unless it was constructed with an ad-hoc
email/password (a setup test must leave no token behind). Methods:
`login(force)`, `ensure_login`, `list_trips`, `get_trip(id)`, `delete_trip(id)`,
`bundle(id)` (returns `{"bundle", "days", "places"}` for verification). CLI:
`python3 engine/trek_api.py health|trips|bundle <id>|delete <id>`. The service
wraps most payloads in a single-key envelope, which the client unwraps.

### `engine/geocode.py`

Nominatim (OpenStreetMap) geocoder, 1 request/second, User-Agent
`travel-desk/1.0 (KiroCrew app; trip planning)`.

```
python3 engine/geocode.py "query" ...                        # TSV: query, lat, lng, display_name
python3 engine/geocode.py --batch <itinerary.json> [--country <iso2>] [--write]
```

`--batch` fills lat/lng for every place and stay missing them; a place that
cannot be resolved is left untouched (never guess a coordinate). `--write` saves
the file back.

## 5. Trip directory and itinerary JSON

```
<desk root>/trips/<slug>/
  request.md                  the leader writes it; every line is analyst input
  research/destination.md  research/transport.md  research/lodging-food.md  research/intel.md
  debate/packed-1.md debate/slow-1.md debate/packed-2.md debate/slow-2.md debate/verdict.md
  itinerary.json              the planner writes it; the §5 contract below
  risk/budget.md risk/safety.md risk/stamina.md risk/summary.md
  brief.md                    the pre-trip briefing
  trek.json                   written after the push: {"trip_id","url","pushed_at","places","days"}
  runs/events.jsonl           desk_event.py appends here
```

Itinerary JSON (contract; real examples are `desk/example-itinerary.en.json` and `desk/example-itinerary.zh.json`, the
authoritative shape is the `engine/push_trip.py` docstring):

```json
{
  "title": "...", "description": "...",
  "start_date": "2026-10-01", "end_date": "2026-10-03", "currency": "AUD",
  "transport_mode": "driving",
  "days": [
    {
      "date": "2026-10-01",
      "notes": "free-text day notes",
      "cards": [
        {"text": "...", "time": "08:00", "icon": "🚗", "color": null}
      ],
      "places": [
        {"name": "...", "lat": 30.2, "lng": 120.1, "address": "...",
         "notes": "...", "time": "09:00", "end_time": "11:00",
         "duration_minutes": 120, "transport_mode": "driving",
         "website": null, "phone": null, "price": null}
      ]
    }
  ],
  "stays": [
    {"name": "...", "lat": 0.0, "lng": 0.0, "address": "...", "from_date": "2026-10-01", "to_date": "2026-10-02",
     "check_in": "15:00", "check_out": "10:00", "confirmation": null, "stay_notes": "...", "notes": "..."}
  ]
}
```

- `transport_mode` (trip level) is the default; per place `transport_mode` is
  the mode of the leg **leaving** that stop (`driving|walking|cycling|transit`).
- `days[].date` is optional; without it a day is matched to the auto-generated
  day by index. `cards` are coloured note cards on the day timeline.
- `stays[]` is optional: a hotel spanning `from_date`..`to_date`.

Hard rules: 3-5 places per day; `time` / `end_time` as `HH:MM`; coordinates must
be real (resolve with `engine/geocode.py`; drop a place you cannot resolve,
never guess); `notes` carry the practical information (why go, what to order,
parking, tickets, closing time); the note cards the risk review asked for are
merged into that day's `cards` during the revise.

**itinerary.json** (planner) — reply's last line `ITINERARY DRAFTED: <path>`
(after a revise, `ITINERARY REVISED: <path>`).

The leader's final report to the traveller (in the request language): the trip
link, one line per day, what it assumed on the traveller's behalf, what is not
in yet (unverified items, missing bookings), and what the risk review changed.

When a fact could not be checked, write "unverified" (en) / "未核实" (zh)
instead of inventing a price, opening time, forecast or phone number.

## 8. The app

### 8.1 Manifest — `app.json`

`name: travel-desk`, `displayName: Travel Desk`, `version 1.0.0`. `agents` lists
the 13 generated `agents/<name>.json`. `skills: ["skills/travel-desk"]`.
`permissions.api`: `["/api/chat", "/api/chat/*", "/api/approvals",
"/api/approvals/*", "/api/file-read", "/api/apps/travel-desk/*"]`;
`network: true`; `cron: false`; `storage: false`.
`backend: {"hooks": {"routes": "backend.routes:register_routes"}}` — hooks only.
Declaring `backend.routes` instead would switch the gateway to the
standalone-process proxy and shadow these handlers.
`ui: {"entry": "index.mjs", "pages": [{"route": "/travel-desk", "label": "Travel
Desk", "iconUrl": "icon.svg"}]}`.
`setup: {"onInstall": "scripts/install.sh", "onUninstall": "scripts/uninstall.sh"}`.

### 8.2 Backend — `backend/routes.py`

In-process: `register_routes(ctx) -> list[AppRoute]`, paths relative to
`/api/apps/travel-desk`, each handler `(request, ctx)`. Unauthenticated callers
get 401; errors return `{"error": msg}`. Every filesystem read is anchored at
`deskRoot` and a slug or path that escapes the tree is refused. On first
registration the backend writes a default `data/config.json` and seeds the desk
root skeleton (idempotent).

- **GET `/status`** → `{"trek": {"url", "reachable", "configured",
  "authenticated", "auth_error", "running", "healthy", "managed", "container":
  {...}}, "setup_needed": bool, "desk_root", "leader_slot": "travel-desk-leader",
  "leader_slot_en": "travel-desk-leader-en", "leader_agent": "trip-tour-leader",
  "version"}`. `running` = the service answered HTTP; `healthy` = reachable and
  the saved login works. Container state comes from `docker inspect`.
- **GET `/setup`** → connection settings the UI may show: `{"trek_url", "email",
  "has_password", "managed", "container", "image", "desk_root", "data_dir",
  "port", "docker_available", "reachable"}`. Never the password or the key.
- **POST `/setup`** → body `{"trek_url"|"url", "email", "password", "test_only"?}`.
  Tests the login; unless `test_only`, saves the URL to config and the login to
  `trek.env`. Auth failure → 502 `{"ok": false, ...}`; bad input → 400. The
  password is never echoed.
- **POST `/service/{action}`**, action ∈ `create|start|stop|restart|upgrade|backup`
  (`SERVICE_ACTIONS`). `create` takes body `{"port", "email", "password"}`,
  writes `trek.env` (generating an at-rest key), and runs the official image
  bound to loopback with state under `<desk root>/trek/`. `start|stop|restart`
  drive the container; `upgrade` is pull → rm → run again (state kept by the two
  `-v` mounts); `backup` tars `<desk root>/trek/{data,uploads}` to
  `<desk root>/backups/trek-<UTC>.tgz` and is only offered for the app-managed
  service. Every step is an argv list (no shell), 300 s timeout. Unknown action
  → 400. Returns `{"ok": true, "action", "output": <stdout tail>}`; a non-zero
  step → 502.
- **GET `/trips`** → `{"trips": [{"id", "title", "start_date", "end_date",
  "day_count", "place_count", "url": "<trek_url>/trips/<id>"}], "error": ""}`.
  Unreachable → `{"trips": [], "error": "..."}` at 200.
- **GET `/trip?id=<n>`** → one trip's view model built from the service's
  `bundle` (see design/API.md for the full shape: `trip`, `days` with sorted
  `items`, `places` map, `stays`, `photos_pending`, `totals`). Non-integer id →
  400; service 404 → 404; unreachable → 502.
- **GET `/photos?id=<n>`** → resolve and cache photos for the trip's places →
  `{"photos": {"<place_id>": "<url|null>"}, "resolved", "missing"}`. Bad id 400
  / 404 / 502.
- **GET `/photo/{place_id}`** → the cached image bytes, `Content-Type` by
  extension, `Cache-Control: public, max-age=86400`. Non-numeric id → 400; no
  cache → 404.
- **GET `/org`** → `{"members": [<members.json entry> + "state":
  "idle|working|blocked", "state_msg", "slot_key"]}`. State is inferred from the
  current trip's events (`?trip=<slug>`, default = the most recently modified
  `runs/events.jsonl`): a member's last event `dispatched|stage` → working,
  `failed` → blocked, else idle. `slot_key`: the leader's fixed slot; residents
  resolved from the gateway sidebar by folder+title; leaves `null`.
- **GET `/run?trip=<slug>`** → `{"trip", "request": <head of request.md>,
  "artifacts": {"<relative path>": bool}, "trek": <trek.json|null>, "events":
  [last 200]}`. No slug → an empty shape.
- **GET `/local-trips`** → `{"trips": [{"slug", "title", "updated_at", "trek"}]}`
  from the `trips/<slug>` directories on disk.

The gateway owns `/api/apps/{name}/config` (the config read); it is not
re-declared here.

### 8.3 UI — `ui/` (ES-module React, `createElement`, no JSX, no bundler)

A single Travel Desk page that reads the trip planner through this backend and
renders inline (nothing is iframed, so no second port is needed).

- **Setup state.** When `/status` reports `setup_needed`, the UI leads the user
  to the settings page to connect or run a trip planner.
- **Trip page** (`ui/trip.mjs`). An Airbnb-style page: hero, day-by-day timeline
  with photos and note cards, a sticky leader chat. Photos are decoration —
  the page stands without them; the UI polls `/photos` a bounded number of times
  while some are pending. The empty state shows when there is no trip in the
  interface language.
- **Map** (`ui/map.mjs`, `ui/mapview.mjs`). A full-screen map with pins and a
  photo card rail (Leaflet). Reached from "see map".
- **Settings** (`ui/settings.mjs`). Interface language (中文 / English), the
  trip data service (status, address, and the advanced start / stop / restart /
  backup controls), and a short about.
- **Per-language leader slot.** The chat binds `trip-tour-leader` on the slot for
  the interface language: `travel-desk-leader` for 中文, `travel-desk-leader-en`
  for English (both reported by `/status`).
- **Trips shown per language by title script.** The crew writes a whole trip in
  the request language, so a trip's title script decides its language (any CJK
  character → 中文, else English). The interface shows only the trips of its own
  language; an English screen never carries a Chinese headline.
- **Interface language default.** When the user has not chosen one, it defaults
  to the browser language: `navigator.language` starting with `zh` → `zh-CN`,
  else `en`.

## 9. Acceptance

**M0 — install + UI + roster.** The app installs into the gateway and "Travel
Desk" appears in the sidebar. The page renders: the leader chat binds
`trip-tour-leader` on the per-language slot; the trip list comes from the trip
planner through `/trips`; the roster of 13 members renders from `/org`.

**M1 — one real trip through the chain lands in the planner.** Telling the
leader one real trip runs the whole chain (planner → analysts → debate → verdict
→ itinerary.json → risk review → optional single revise → push) and a new trip
appears in the trip planner. `trips/<slug>/` holds the full set of §5 artifacts,
`runs/events.jsonl` has dispatched/delivered events, and the roster states change
as the run proceeds.

## 10. Change process

1. Change this file first (the authoritative interface), then bring the code to
   match; the code is what ships.
2. If the desk's behaviour changed, update `desk/CHARTER.md` and bump its
   `Version:`.
3. If the org or a field changed, update `desk/members.json` and the affected
   `agents/prompts/<name>.md`, then run `scripts/build_agents.py`.
4. Run `python3 engine/orchestrate.py plan --trip <an existing slug> --intent
   full` to confirm the plan still holds, and the test commands in §8.4.
5. A specific trip or a lesson is memory, not contract: append to
   `<desk root>/memory/lessons.md`, never edit this file or a prompt.
